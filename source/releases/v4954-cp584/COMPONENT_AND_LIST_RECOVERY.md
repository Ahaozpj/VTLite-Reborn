# CP584 — восстановление компонентов и списка диалогов

Собственные изменения, извлечённые из точного публичного v4954. Частичный комплект; не самостоятельная сборка.

## Доказательства

- SHA-256 оригинала: `2c312fecefce700bae0a956227f79474a6e17da64e93f22f0cb98d4e0436bb30`.
- SHA-256 релиза: `5f6f67d33141e398e97f951f68a83fa35d1c02bedf99a2e31f2bb714b521a3a8`.
- Четыре класса отсутствуют в семи DEX оригинала. Предыдущие варианты найдены в сохранённых архивах CP527, CP537, CP556, CP561. После сборки smali и обратного декодирования baksmali 3.0.10 все 4 финальных класса совпадают байт-в-байт с декодированными классами из classes3.dex v4954. CP537 совпадает и с канонической сборкой архивного исходника; остальные три имеют более поздние изменения в собственной логике списка и жизненного цикла. Это восстановленный Smali релиза, а не утверждение о побайтовом совпадении с историческим Java или исходным оформлением Smali.
- Патч четырёх унаследованных классов (профиль, браузер, звук входящего звонка, обновление списка стикеров) воспроизводит точные целевые Smali 4/4; пять негативных проверок отклонены (неверные APK, область манифеста, исходный класс, целевой хеш, существующий каталог результата). Чужие тела классов не включены.
- Никаких ключей, APK, DEX, данных пользователей или приватных журналов не включено. Проверены строки и назначение четырёх собственных классов; полной независимой проверки безопасности приложения не заявляем.

## Применение патча

Требуются Python 3, законно полученный оригинальный APK с указанным SHA-256 и локально декодированные его DEX в каталогах `classes`, `classes2` … `classes7` через baksmali 3.0.10. Выполнить `python patches/patch_component_package.py ORIGINAL.apk DECODED NEW_OUTPUT`. Каталог результата должен отсутствовать. Все четыре входных и выходных класса проверяются по манифесту до записи. Это только четыре изменённых класса, не полное дерево для сборки.
