# Публикация APK в GitHub Releases

Это руководство для владельца репозитория. Разработка, подпись APK и внутренние документы находятся отдельно от публичного репозитория.

## Первый выпуск: CP205

**До публикации:** убедиться, что распространение APK допустимо с учётом прав на исходный клиент и встроенные компоненты. Не помещать закрытый ключ, пароль к нему, токены, файлы сессии и собственные переписки в публичный репозиторий.

1. Откройте [новый выпуск](https://github.com/Ahaozpj/VTLite-Reborn/releases/new). Если форма на телефоне не показывает поле для вложений, откройте GitHub в браузере в режиме «Версия для ПК».
2. Укажите тег **`v4850-cp205`** (создать новый тег).
3. Заголовок: **`VTLite Reborn — CP205 (4850)`**.
4. В описание можно перенести раздел «Подтверждено пользователем» и «Ограничения» из [CP205.md](releases/CP205.md).
5. Прикрепите **ровно подписанную APK** `VTLite_Reborn_CP205_SameSigner_Update_v4850.apk` в раздел **Assets**. Исходник для владельца находится на его Google Drive. **Не** публикуйте файл ключа подписи `.p12`, пароль, внутренние архивы и диагностические логи.
6. Сверьте размер APK: **78 522 511 байт** и SHA-256: **`e08a783a97a2a36bcfc86681750074b6b2ec9442cf0be3b593f0dc1eae3c0534`**. Если байты отличаются — не публикуйте с этой контрольной суммой.
7. Первую версию разумно отметить как **Pre-release** (тестовое распространение), поскольку вход был проверен только на одном аккаунте.
8. Нажмите **Publish release**. После этого проверьте, что раздел **Assets** содержит APK и скачивание доступно в браузере без входа в GitHub.

Ссылка на выпуск после публикации: https://github.com/Ahaozpj/VTLite-Reborn/releases/tag/v4850-cp205

Прямая ссылка на APK **начнёт работать только после публикации соответствующего asset**:

https://github.com/Ahaozpj/VTLite-Reborn/releases/download/v4850-cp205/VTLite_Reborn_CP205_SameSigner_Update_v4850.apk

Готовую версию можно сообщать пользователям через ссылку на **Releases**: https://github.com/Ahaozpj/VTLite-Reborn/releases . Для следующей версии добавляется новый выпуск, не перезаписывается файл CP205.

**Техническое ограничение подключённого GitHub-инструмента:** здесь доступны создание и изменение текстовых файлов репозитория, но нет операции загрузки 78-МБ бинарника в GitHub Release. Первый APK необходимо загрузить вручную через интерфейс GitHub либо другим отдельно настроенным каналом авторизованной публикации.

## Контроль качества

- Не публиковать APK, если невозможно подтвердить SHA-256 и подпись.
- В публичном README описывать только реальные пользовательские тесты.
- Не считать успешную авторизацию на одном устройстве гарантией работы на новом аккаунте.
- Соблюдать права на сторонние компоненты.
